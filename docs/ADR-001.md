# ADR-001: Shell and UI technology

Status: Accepted (Phase 1) · Date: 2026-11-05

## Decision
Tauri 2 (Rust core, `windows` Win32/WinRT access where needed) + WebView2 rendering + TypeScript/React frontend. NSIS bundle target with `installMode: both`: users choose per-user (no admin, default) or all-users/Program Files (admin) during setup. User data always lives in the user's `%APPDATA%\com.irumva.notch`.

## Justification
- Verified against Tauri 2 official docs (v2.tauri.app/start/prerequisites, /distribute/windows-installer, /reference/config): Windows requires MSVC C++ Build Tools + WebView2 (preinstalled on Windows 11); NSIS produces a `-setup.exe`; `installMode: currentUser` needs no admin and writes uninstall metadata under HKCU, which is what makes the app appear in Windows Settings > Apps.
- Small footprint vs Electron (system WebView2, no bundled Chromium) supports the <80 MB budget in section 6 of the brief.
- Rust core gives direct Win32 access for WS_EX_NOACTIVATE / WS_EX_TOOLWINDOW, fullscreen detection and (later) SMTC/consent-store providers without a second runtime.
- Strict CSP is a first-class Tauri config key (`app.security.csp`); no remote content is loaded.

## Alternative considered
.NET 8 + WinUI 3 / Windows App SDK + Inno/WiX. Rejected for v1: larger runtime, XAML island morphing is not obviously faster, and the brief's fallback trigger ("WebView2 cannot hold 60 fps") is a measurable gate, not yet triggered. Revisit if Phase 6 frame-time budgets fail on the diagnostics page: the TS state machine, event bus and tokens are framework-free and port unchanged.

## Consequences
- Build machine needs: Rust (stable-msvc), VS C++ Build Tools (present: VS 18 BuildTools), WebView2 (present: 156.0.4314.58).
- Frontend logic must stay portable (pure TS core, no Tauri imports outside `app/src/platform/`).
